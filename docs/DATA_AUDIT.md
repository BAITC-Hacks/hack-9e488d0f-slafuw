## 3. Календарь

Известно 100 календарных дней включительно: 23 сентября — 31 декабря 2026. Дата — день мероприятия, без времени суток и пересечений слотов.

| Месяц | Известных дней | Занято профиль-дней / всего | Доля занятости | На выходных |
|---|---:|---:|---:|---:|
| Сентябрь | 8 | 218 / 528 | 41,29% | 46,21% |
| Октябрь | 31 | 789 / 2 046 | 38,56% | 44,95% |
| Ноябрь | 30 | 803 / 1 980 | 40,56% | 47,47% |
| Декабрь | 31 | 1 527 / 2 046 | 74,63% | 78,22% |

Это среднее по всем профилям, а не вероятность свободного подрядчика для любого запроса. После бюджета, формата и языка выборка уменьшается: например, 12 декабря три подходящих англоязычных ведущих Алматы заняты все.

Дата, отсутствующая в `busy_dates`, считается свободной **только внутри известного окна**. За его пределами отсутствие записи не доказывает доступность: API возвращает понятную ошибку валидации.

Календарь действует и для площадок, и для флористов, и для сувениров. `max_hours=null` не выключает проверку даты.

## 4. Особенности схемы

### CSV

Массивы разделены `|`. Значения `True`/`False` переводятся строго в boolean; применять `bool("False")` нельзя, это даст `True`. Пустое поле часов превращается в `null`, цена — целое число тенге. Текст описания сохраняется без перефразирования, чтобы работали точные ссылки на источники.

### Денежная модель

Все `price_from_kzt` трактуются согласно треку: **тенге за мероприятие**. Нельзя умножать цену площадки на гостей, делить на часы или автоматически рассчитывать доплату: этих тарифных правил нет.

У всех восьми профилей категории «Банкетный зал» цена помечена `price_imputed=true`. Поэтому именно в демо площадок важно показать происхождение значения, сохранив его пригодность для фильтрации по правилам набора.

### `null` в часах

9 профилей — по три флориста, декоратора, поставщика подарков. Продолжительность присутствия для них неприменима. Верное объяснение: «ограничение по часам присутствия неприменимо», а не «работает без ограничения времени».

### Синтетика

У 7 редких категорий покрытие частично поддерживается синтетическими профилями организаторов. Карточки с `synthetic=false` называются «Исходный анонимизированный профиль»: это не обещание независимой проверки личности или качества.

Если команда позднее добавит записи, одного boolean будет недостаточно для отличия происхождения: нужен внешний манифест `id → organizer / team`, а в UI отдельная метка «Синтетический профиль команды». Текущая версия использует только организаторский набор.

## 5. Смысловые противоречия и ограничения текста

| Пример | Наблюдение | Решение |
|---|---|---|
| Кики, `HK-35215` | В описании есть конференции, в `event_formats` их нет | Для допуска приоритет у `event_formats`; текст не расширяет список |
| Хаул, `HK-77838` | `languages` содержит русский и казахский, текст отдельно говорит «Язык проведения: казахский» | Не переписывать структурированное поле; аккуратно выбирать цитаты |
| Рок Ли, `HK-68220` | В описании есть концерты, в списке форматов свадьба, той, юбилей | Не выдумывать новый поддерживаемый формат |
| Леорио и другие | Упоминают работу в других городах и странах | Город определяется полем `city`, не рекламным текстом |
| Лайв-бэнды | Несколько почти одинаковых рекламных абзацев | Искать конкретику состава и репертуара, не копировать общие прилагательные |
| Анонимизированные профили | Имена, род и названия в текстах иногда расходятся | Идентификатор — `id`, имя карточки — `anon_name`; избегать придуманных биографий |
| Звания и рейтинги | «Топ», «№1», «лучший» — заявления в описании | Не превращать их в числовую оценку качества |

Медицинские и другие специальные рекламные обещания из описаний не нужны для выбора event-подрядчика. Целевой извлекатель должен предпочитать тип продукта, формат, стиль и состав услуги, а не переносить такие обещания в рекомендации.

## 6. Что валидируется автоматически

- Наличие точного набора полей профиля.
- Непустые текстовые идентификатор, имя, город, описание.
- Типы boolean, массивов, положительной цены и часов.
- Допустимые форматы и языки.
- Уникальность `id` и элементов массивов.
- Корректные ISO-даты календаря и известный диапазон.
- SHA-256 канонического файла соответствует манифесту.

Семантические противоречия описаний не «чинятся» импортом. Они перечислены в этом документе; структурированные поля остаются источником правил.

## 7. Практический вывод

Объём данных позволяет держать всё в памяти и проверять кандидатов полным перебором. Главная техническая сложность — корректная интерпретация полей, объяснения, диагностика и воспроизводимость. Отдельный поисковый кластер или обучение модели не решают эти проблемы.
