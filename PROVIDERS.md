# OpenAI + NVIDIA: запуск агента

## Фактический статус

Реализованы сетевые клиенты OpenAI Responses API и NVIDIA Embeddings API, подготовка
артефакта, function calling, SQLite-состояние и журнал, серверная проверка объяснений.
Ключи читаются **только в серверном процессе**: из его окружения либо локального `.env`
в корне проекта при запуске `serve`/`agent`. Процессное окружение имеет приоритет.
Файлы credentials приложение не читает, браузеру ключи не передаются. `.env` исключён
из Git через `.gitignore`; не публикуйте его и не включайте в архивы с проектом.

Для NVIDIA-артефакта нужен отдельный ключ NVIDIA; готовый артефакт не прилагается.
Если NVIDIA-ключ задан в локальном `.env`, команда подготовки также его загружает.
Автотесты провайдеров используют явно обозначенные тестовые ответы, не демонстрационные
«результаты NVIDIA». Без настройки сервер работает в `deterministic baseline`.
OpenAI проверен живыми запросами на `gpt-5.5`: извлечение условий и выбор
проверенных оснований в структурированной форме сработали. В одном полном текстовом
запросе третий вызов не уложился в общий deadline 10 секунд, и сработал шаблонный
fallback без изменения списка карточек.

## Подготовка и запуск

Нужен Python 3.11+. Зависимости — стандартная библиотека.
Локальный `.env` либо серверное окружение должны содержать `OPENAI_API_KEY` и `NVIDIA_API_KEY` для полного режима.
Имена всех переменных приведены в [примере конфигурации](../.env.example).

Из корня проекта в PowerShell:

```powershell
# Ключи уже переданы серверу через окружение.
$env:OPENAI_MODEL = 'gpt-4.1-mini-2025-04-14'
$env:NVIDIA_EMBEDDING_MODEL = 'nvidia/llama-3.2-nv-embedqa-1b-v2'
python -X utf8 -m tools.prepare_semantics --output data/nvidia-artifact.json
```

Команда действительно отправляет описания и намерения в NVIDIA, сохраняет векторы,
целочисленные оценки, версии, точные цитаты, хеши и сведения о завершённых API-вызовах.
При ошибке старый артефакт сохраняется. Включать семантический режим следует после
успешной подготовки:

```powershell
$env:EVENTMATCH_RANKER = 'nvidia'
$env:EVENTMATCH_NVIDIA_ARTIFACT = 'data/nvidia-artifact.json'
python -X utf8 -m eventmatch serve
```

Открыть **http://127.0.0.1:8000**. Для проверки заполненного заказа через CLI:

```powershell
python -X utf8 -m eventmatch agent --request examples/01-dense.json
```

`GET /metadata` показывает выбранный ranker и версию артефакта.
`openai_configured=true` означает только наличие серверной настройки, не доказательство
успешного запроса. Доказательство фактического обращения — запись OpenAI в `actions`
с `status=succeeded` и `response_id`. NVIDIA в выдаче помечается как **prepared artifact;
no online embedding call**: во время подбора нового запроса к NVIDIA нет.

Явный локальный режим:

```powershell
$env:EVENTMATCH_RANKER = 'baseline'
python -X utf8 -m eventmatch serve
```

При `EVENTMATCH_RANKER=nvidia` отсутствующий, неполный или несовместимый артефакт
останавливает запуск. Автоматического переключения ranker при сбое нет.

## Проверенный контракт NVIDIA

Проверено по документации 24.09.2026:

- модель: `nvidia/llama-3.2-nv-embedqa-1b-v2`;
- endpoint: `POST https://integrate.api.nvidia.com/v1/embeddings`;
- заголовок `Authorization: Bearer …`;
- `model`, `input`, `input_type=passage|query`, `encoding_format=float`, `truncate=NONE`;
- фрагменты description отправляются с `passage`, канонические «категория + формат» — с `query`;
- русскому языку посвящена явная запись в перечне 26 языков в model card NVIDIA;
- hosted API указывает лимит 512 токенов, model card весов — 8192. Клиент не полагается
  на больший лимит: текст не обрезается, превышение даёт ошибку подготовки;
- точная ревизия hosted-весов API не раскрыта: это явно указано в артефакте.
  Воспроизводимость выдачи опирается на сохранённые значения и SHA-256 артефакта.

Источники:

- [NVIDIA OpenAPI reference](https://docs.api.nvidia.com/nim/reference/nvidia-llama-3_2-nv-embedqa-1b-v2-infer)
- [Model card NVIDIA: языки и архитектура](https://huggingface.co/nvidia/llama-3.2-nv-embedqa-1b-v2)

Другой идентификатор embedding-модели отклоняется до отдельной проверки её контракта.
Векторы не считаются рейтингом качества. Оценка профиля — максимум cosine по его фрагментам,
округлённый до целого после умножения на 1 000 000. Ключ сортировки:
`(-score_int, price_from_kzt, id)`. Семантического порога допуска нет.

## OpenAI и состояние диалога

Endpoint — `POST https://api.openai.com/v1/responses`. По умолчанию используется
фиксированный snapshot `gpt-4.1-mini-2025-04-14`; `OPENAI_MODEL` меняет его на стороне сервера.
При `OPENAI_MODEL=gpt-5.5` клиент выставляет `reasoning.effort=none` для меньшей задержки.
`store=false`, строгие JSON-схемы, последовательные function calls, без сетевых повторов.

Зарегистрированы `get_catalog_metadata`, `recommend`, `compare_dates`, `finalize_result`
и внутренний инструмент `update_order`. Последний извлекает намерение, изменения полей
и подтверждающие фрагменты пользовательского сообщения. Код сливает только изменения
со структурированным заказом. Неуказанные язык/часы остаются `null`.

Заполненный текстовый запрос обычно требует трёх обращений OpenAI: извлечение изменений,
вызов подбора, пакетный выбор оснований для трёх карточек. Для структурированной формы
нужен только выбор оснований. Нет отправки всех 66 профилей модели.
Год берётся из сообщения, предыдущего заказа или явного `EVENTMATCH_DEFAULT_YEAR`;
календарное окно само по себе не задаёт год.

Backend собирает объяснение из 1–2 разрешённых фактов и одной полной точной цитаты.
Свободный рекламный текст модели не публикуется. План с чужим источником, новым ID,
дубликатом или дополнительными полями отклоняется; затем применяется шаблон.
Порядок карточек восстанавливается из сохранённого результата, а не плана.

Общий бюджет сетевой работы — 10 секунд на запрос. При недоступности генерации или
исчерпании времени возвращаются те же карточки с `template explanation fallback`.
Если не удалось даже разобрать новое сообщение, возвращается `technical_error`, а не
выдача по старому заказу. Форма при этом доступна.

Источники:

- [OpenAI function calling](https://platform.openai.com/docs/guides/function-calling)
- [GPT-4.1 mini, snapshot и поддержка Responses](https://platform.openai.com/docs/models/gpt-4.1-mini)

## Сохранение и проверка

`EVENTMATCH_DB` по умолчанию — `data/eventmatch.sqlite3`:

- `sessions`: структурированный заказ и предыдущий окончательный ответ;
- `results`: исходный зафиксированный набор карточек с разрешёнными фактами и цитатами;
- `actions`: фактически исполненные инструменты, нормализованные аргументы, отказы,
  выбранные IDs и источники, версии и длительности. Скрытые рассуждения не сохраняются.

Идентичные заказ, каталог, ограниченный набор профилей и ranker дают одинаковый `result_id`
и порядок карточек после перезапуска. `session_id`, `trace_id`, времена запросов и выбор
цитат OpenAI не обязаны совпадать. Вопрос об основаниях возвращает **сохранённое**
объяснение и его исходный журнал.

```console
python -X utf8 -m unittest discover -s tests -v
python -X utf8 -m tools.check_repository
```

Legacy-команда `eventmatch recommend`, `tools.demo` и `examples/responses` остаются
воспроизводимым контролем лексического ядра; активный агент вызывается через сервер
или `eventmatch agent`. Старые измерения benchmark относятся именно к этому ядру,
не к задержке OpenAI или полному сетевому ответу.
