# EventMatch · умный подбор подрядчиков (#79-lite)

**Из каталога города — до трёх подходящих подрядчиков с объяснением по данным профиля.**

EventMatch помогает организатору мероприятия сравнить подрядчиков, когда каталог уже задан. Сервис не расширяет список за счёт внешнего поиска: он проверяет условия заказа, исключает неподходящие профили и объясняет, чем отличаются оставшиеся варианты. Это решение трека «Умный подбор подрядчиков» для каталога Казахстана.

## Быстрый запуск

Нужен Python 3.11 или новее. Внешние Python-пакеты для запуска не требуются.

```console
python -X utf8 -m eventmatch serve
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Сервер доступен только на локальном компьютере. Остановить его можно клавишами `Ctrl+C`.

Без API-ключей доступны форма, HTTP API и детерминированный baseline с шаблонными объяснениями. Свободный текстовый чат использует OpenAI и без его настройки недоступен. Для NVIDIA-ранжирования дополнительно нужен подготовленный семантический артефакт.

## 1. Название

**EventMatch** — умный подбор event-подрядчиков, проект хакатона #79-lite.

## 2. Проблема и пользователи

Заказчик уже получил каталог подрядчиков для своего города и типа мероприятия. Ему нужно выбрать из него, не пропустив занятых или не подходящих по бюджету и условиям. EventMatch показывает до трёх допустимых вариантов и даёт проверяемые основания для сравнения вместо общей рекламной формулировки.

## 3. Что реализовано

- Подбор по городу, дате, формату мероприятия, категории и бюджету; язык и длительность — дополнительные условия.
- Общие правила допуска для людей, коллективов и площадок. Профиль, занятый в календаре на выбранную дату, не попадает в выдачу.
- Три различимых бизнес-исхода: `matched`, `no_category_in_city`, `no_match`. Некорректный ввод возвращается отдельно как ошибка валидации.
- Стабильная выдача до трёх карточек, причины исключения, сведения о числе допустимых профилей и проверенные подсказки для изменения даты или бюджета.
- Объяснения из структурированных условий и точных цитат профиля. Для fallback цитаты отбираются совместно для top-3; общая похвала, списки клиентов и фразы, отрицающие выбранный формат, не используются как evidence.
- Метки синтетических профилей и значений цены/города, проставленных при подготовке набора.
- HTML-форма, локальный HTTP API, CLI, чат с изменением параметров, сравнение дат и вопрос «почему?».
- OpenAI function calling для разбора свободного текста и выбора разрешённых фактов/цитат. Backend проверяет план объяснения, сохраняет состав и порядок карточек.
- Подготовка NVIDIA embeddings и поддержка замороженного семантического ranker. Артефакт NVIDIA в репозиторий не включён; без него используется baseline.
- SQLite для состояния диалога, результатов и журнала действий. Секреты провайдеров нужны только серверу и передаются через переменные окружения.

## 4. Как работает подбор

Пользователь задаёт город, дату, формат, категорию, бюджет и, если нужно, язык и часы. Сервис сначала находит исходную группу по точным значениям `city + category`, затем проверяет календарь, цену, формат, язык и длительность. Ранжирование применяется **только к прошедшим все ограничения**.

```text
Запрос
  → валидация полей и даты
  → группа города и категории из исходного каталога
  → жёсткая проверка условий и запись причин отказа
  → детерминированное ранжирование допустимых
  → до 3 карточек с фактами и точными цитатами
```

В baseline порядок задаётся релевантностью описания формату, затем стартовой ценой и `id`. Это прозрачная эвристика, а не оценка качества подрядчика. OpenAI не выбирает кандидатов и не меняет их порядок: он может разобрать запрос и выбрать объяснения только из разрешённых источников.

## 5. Технологии и AI

| Область | Технология |
|---|---|
| Backend и CLI | Python 3.11+, стандартная библиотека, `dataclasses`, `unittest` |
| HTTP | `http.server` и `ThreadingHTTPServer`, без отдельного web-фреймворка |
| Интерфейс | HTML, CSS и vanilla JavaScript, одна страница |
| Сохранение состояния | SQLite через стандартный модуль `sqlite3` |
| LLM, опционально | OpenAI Responses API, function calling; модель по умолчанию `gpt-4.1-mini-2025-04-14` |
| Эмбеддинги, опционально | NVIDIA Embeddings API, `nvidia/llama-3.2-nv-embedqa-1b-v2`; оценки рассчитываются заранее и сохраняются в артефакт |

Живые запросы OpenAI также проверялись с `gpt-5.5`; это не модель по умолчанию. Без подключённого NVIDIA-артефакта фактический ranker — deterministic baseline. Вызовы провайдера могут завершиться таймаутом: тогда остаётся шаблонное объяснение, а жёсткие условия, состав карточек и порядок не меняются.

## 6. Архитектура проекта

- `eventmatch/models.py` — схема запроса и профиля, проверка типов и календарного диапазона.
- `eventmatch/catalog.py` — загрузка каталога и его версия.
- `eventmatch/engine.py` — исходная группа, жёсткие ограничения, baseline-ранжирование, диагностика и извлечение цитат.
- `eventmatch/service.py` — инструменты подбора, формирование фактов, проверка источников и сборка ответа.
- `eventmatch/agent.py` — OpenAI function calling, диалоговое состояние, deadline и fallback.
- `eventmatch/providers.py` и `eventmatch/semantic.py` — клиенты OpenAI/NVIDIA и подготовка/проверка семантического артефакта.
- `eventmatch/storage.py` — SQLite-сессии, снимки результатов и журнал действий.
- `eventmatch/server.py` — локальный HTTP-адаптер; `web/index.html` — форма и карточки.
- `examples/`, `tests/`, `tools/` — контрольные запросы и ответы, тесты, аудит данных и демосценарии.

Доменный подбор выполняет backend и он же остаётся источником истины. Модель не может расширить каталог, пропустить ограничение, добавить профиль или подменить цитату. Перед выдачей backend проверяет принадлежность fact/evidence ID конкретной карточке.

## 7. Установка и запуск

1. Установите Python 3.11+.
2. Откройте терминал в корне репозитория. Установка зависимостей не нужна.
3. Запустите приложение:

   ```console
   python -X utf8 -m eventmatch serve
   ```

4. Перейдите на `http://127.0.0.1:8000` и выберите демосценарий или заполните форму.

Другой порт можно указать так:

```console
python -X utf8 -m eventmatch serve --port 8080
```

`-X utf8` рекомендуется в Windows для корректного вывода кириллицы.

### Необязательные провайдеры

Ключ OpenAI задаётся в окружении процесса сервера. Например, в PowerShell:

```powershell
$env:OPENAI_API_KEY = "<ключ>"
python -X utf8 -m eventmatch serve
```

Чтобы использовать NVIDIA ranker, сначала подготовьте артефакт с NVIDIA API, затем запустите сервер в этом режиме:

```powershell
$env:NVIDIA_API_KEY = "<ключ>"
python -X utf8 -m tools.prepare_semantics --output data/nvidia-artifact.json
$env:EVENTMATCH_RANKER = "nvidia"
$env:EVENTMATCH_NVIDIA_ARTIFACT = "data/nvidia-artifact.json"
python -X utf8 -m eventmatch serve
```

Артефакт зависит от каталога и версии алгоритма. Если выбран NVIDIA-режим, но артефакт отсутствует или несовместим, сервер остановится, а не переключится незаметно на baseline. Подробности конфигурации и API — в [инструкции по провайдерам](docs/PROVIDERS.md).

## 8. Как проверить решение

Демо пересчитывает запросы по текущему каталогу, а не воспроизводит сохранённые ответы:

```console
python -X utf8 -m tools.demo
```

Повторить один сценарий через CLI:

```console
python -X utf8 -m eventmatch recommend --request examples/01-dense.json
```

Для жюри: запустите сервер и выберите **«Ведущие · 12 октября»**. Запрос: Алматы, ведущий, корпоратив, 12 октября 2026, бюджет 1 300 000 ₸, 6 часов, русский язык. Baseline находит 7 допустимых профилей и показывает до трёх; при изменении только даты на 13 октября состав top-3 меняется из-за занятости одного из кандидатов. Другие кнопки показывают редких флористов, пустую выдачу и отсутствие категории в городе.

Запустить автоматические тесты:

```console
python -X utf8 -m unittest discover -s tests -v
```

Текущий набор содержит 51 тест, включая проверку ограничений на 100 дат контрольного запроса, детерминизма, источников цитат, API, агента и fallback. Контракт HTTP описан в [docs/API.md](docs/API.md), происхождение и распределения данных — в [docs/DATA_AUDIT.md](docs/DATA_AUDIT.md).

## 9. Данные и интеграции

- Встроенный `data/raw/hackathon-dataset-anonymized.jsonl` содержит 66 профилей из предоставленного CSV; HTML-превью не используется как источник календарей.
- В каталоге 17 категорий: Алматы — 50 профилей, Астана — 15, «Зарубежье» — 1. Мультикатегорийные профили не дублируются в выдаче.
- 13 профилей помечены `synthetic=true` организаторами. Команда новых профилей не добавляла. Поля `city_imputed` и `price_imputed` отображаются как отдельные метки.
- Известный календарь покрывает только даты с 23 сентября по 31 декабря 2026 года. Отсутствие записи о занятости трактуется согласно этому каталогу и только внутри заданного окна.
- OpenAI вызывается сервером для разбора диалога и/или выбора оснований. NVIDIA используется при подготовке embeddings и артефакта. В браузер API-ключи не передаются.
- При обычном запуске сеть и внешние API не нужны.

Цена `price_from_kzt` — цена «от» за мероприятие, а не итоговая смета. `max_hours = null` означает, что ограничение часов присутствия неприменимо, а не что подрядчик готов работать неограниченно.

## 10. Ограничения текущей версии

- Лексические признаки и эвристики цитирования не являются полноценным пониманием языка. Они не гарантируют выявление всех сложных отрицаний и смысловых связей; полезность объяснений требует отдельной человеческой оценки.
- Цитата подтверждает только то, что утверждение присутствует в описании профиля. Она не подтверждает его независимо.
- Данные ограничены 66 профилями и календарём до конца 2026 года; актуальные цены, доступность, рейтинги, успешность заказов и итоговые сметы не проверяются.
- В запросе поддерживается один язык. Фильтра по числу гостей и другим не представленным в схеме условиям нет.
- Бронирование, заявки подрядчикам, уведомления и публичное размещение не реализованы. Сервер предназначен для локального демо и слушает только `127.0.0.1`.
- Публичной deployed-версии и настроенного CI workflow в текущем репозитории нет; тесты запускаются локально.

## 11. Развёрнутая версия

Публичной deployed-версии нет. Для демонстрации запустите локальный сервер по инструкции выше: `http://127.0.0.1:8000`.
